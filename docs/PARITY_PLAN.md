# План сближения с GanttPRO

Сверка: живой интерфейс GanttPRO и Gantt Desktop 0.9.0. Это очередь отдельных рабочих изменений, а не заявление о полном совпадении приложений. Каждый этап закрывается после тестов; открытые пункты не считаются реализованными.

Объём: задачи, диаграмма Ганта, локальные ресурсы проекта. Доска, аккаунты, портфели, комментарии и межпроектная загрузка не входят в план. Не использовать исходники старого GanttProject или код/ассеты GanttPRO.

## Порядок реализации

### 1. Работа с датами — календарь готов в 0.10, почасовая шкала остаётся

- [x] Календарь выбора начала и завершения в свойствах задачи и в таблице.
- [x] Выбор даты сохраняет время, учитывает рабочий календарь и существующие ограничения зависимостей.
- [x] Отмена ничего не меняет; применение — одна операция Undo/Redo, включая пересчитанные задачи.
- [ ] Полноценная почасовая шкала и заголовки диаграммы — отдельное последующее изменение (после основных модулей ниже).

### 2. Независимый дедлайн — готово в 0.10

- [x] Необязательная календарная дата «Крайний срок», отдельная от планового завершения.
- [x] Установка, изменение и удаление через календарь; сохранение в проекте и Undo/Redo.
- [x] Видимое предупреждение о нарушении срока; изменение дедлайна не перестраивает расписание.
- [x] Отображение и перенос в экспортах там, где формат это поддерживает.

Договорённость для первого варианта: дедлайн — дата местного календаря проекта, включительно до конца этого дня, а не ограничение планировщика и не новое время завершения.

Проверка 0.10: 453 теста, Ruff и активная Python LSP-диагностика ошибок; установленный wheel проверен на календаре/Undo, узком тёмном окне и всех пяти форматах экспорта. Подробности и ограничения — [Календарь дат и крайний срок](DATES_AND_DEADLINES.md).

### 3. Исключения календарей — готово в 0.11

- [x] Редактор праздников/исключений рабочего календаря проекта.
- [x] Отпуска и нестандартные часы ресурса на конкретные даты или диапазоны.
- [x] Согласованное отображение ёмкости, загрузки и предупреждений; безопасное сохранение и история.

[Реализация и границы](CALENDAR_EXCEPTIONS.md): непересекающиеся включительные диапазоны, нерабочие дни или до двух рабочих интервалов проекта; ресурсная доступность 0–24 ч/день без переноса задач. Schema 6 читает старые схемы 1–5. Проверены 532 теста, Ruff, Python LSP и установленный wheel с реальными редакторами/Undo/пятью экспортами на изолированном дисплее. Годовая сетка, повторяющиеся правила, ночные смены и автоматическое выравнивание не заявляются.

### 4. Критический путь — готово в 0.12

- [x] Расчёт критических задач и связей с учётом поддержанных зависимостей и рабочего времени.
- [x] Управление подсветкой на диаграмме; объяснимые результаты и проверки на независимых примерах.
- [x] Не выдавать обычную цепочку предшественников за рассчитанный критический путь.

[Правила и границы](CRITICAL_PATH.md): текущие даты — нижние границы, горизонт — завершение полного плана; рабочие минуты и все четыре типа связей. Сводные min/max-границы решаются точными альтернативами, без двойного счёта длительности или ложной критичности всех детей. При превышении бюджета/невалидном плане нет частичных результатов. Ресурсы, дедлайны и фактическое время не превращаются в скрытые ограничения. 603 теста, включая 71 новую проверку и независимый полный перебор небольших расписаний; установленный wheel проверен на реальном переключателе, темах, свойствах и экспорте. Schema 6 не изменилась.

### 5. Базовые планы — готово в 0.13

- [x] Явно сохраняемый исходный план, не связанный с буфером Undo.
- [x] Сравнение текущих дат с базовыми на диаграмме и в полях.
- [x] Создание, выбор и удаление базового плана с сохранением в файле.

[Реализация и границы](BASELINES.md): именованные снимки дат/типов/имён всех элементов по ID, выбор в файле, серые полосы и четыре read-only поля; Δ — календарные часы, не рабочий резерв. Новые элементы остаются без базовых данных, удалённые записи сохраняются в снимке. Выбор не восстанавливает расписание, создание/выбор/удаление участвуют в Undo. Schema 7 читает схемы 1–6. 669 тестов, включая 66 новых; установленный wheel проверен на настоящем переносе блока, повторном открытии без истории и пяти экспортных форматах; Excel даты/время и числа проверены независимым openpyxl. Восстановление проекта и базовые стоимости не заявляются.

### Дополнение 0.14 — перенос файлов, частичная совместимость

- [x] GanttPRO / MSPDI XML → Desktop: нативная проверка дерева/дат/связей и предупреждений, импорт новым несохранённым проектом, сохранение источника.
- [x] Недельные рабочие интервалы из XML и schema 8 с чтением схем 1–7.
- [x] Desktop → GanttPRO CSV: отдельный пресет без заголовков, полная иерархия, даты/время/часы и описания; проверен реальным импортом в удалённом после проверки тестовом проекте.
- [ ] Полный двусторонний перенос со стрелками и всеми метаданными: GanttPRO не принимает XML (переименование в MPP не помогает), а CSV не создаёт связи. Нужен подтверждённый MPP-маршрут; это не считается завершённой полной совместимостью.

[Маршруты, точные поля и ограничения](INTERCHANGE.md). Проверены 20 элементов и 14 связей исходного XML; на сайте сохранены дерево/веха и нестандартные времена 10:00/15:00, но не стрелки. Исходный проект не изменён. 739 локальных тестов, включая 70 новых проверок переноса.

## Проверка каждого этапа

- Доменная валидация, старые файлы, сохранение/загрузка, атомарность и Undo/Redo.
- Реальный ввод в Qt, отмена, ошибочные значения, ограничения и жизненный цикл редакторов.
- Светлая и тёмная темы, узкое окно, отсутствие ошибок QML.
- Только изолированная GUI-автоматизация через `tools/isolated-gui.sh`; не открывать окна на рабочем столе пользователя.
- Полный набор тестов и Ruff перед завершением этапа. Совместимость с MS Project и Windows/macOS подтверждать отдельными проверками, а не наличием экспортёра/поддержки Qt.
