# Каскадная сортировка: проверка GanttPRO

28.10.2026. Проверен живой интерфейс в headless-браузере, без чтения кода или внутреннего состояния сайта. Это результаты исследования, **не реализация сортировки в Desktop 0.18**.

## Контрольный пример

Создан одноразовый проект `GD Cascade TEST 20261028` (`1793137922420`): восемь задач, две вложенные группы, одна связь. Начальное дерево намеренно не упорядочено по датам.

CSV без заголовка содержал четыре поля: WBS, имя, начало и завершение. В мастере выбраны «Нумерация задач», «Название задачи», «Начало», «Завершение» и формат `DD.MM.YYYY`; вехи не назначались. Связь **Y same long → Z late child, ОН/FS, лаг 0** добавлена отдельно через редактор зависимостей до фиксации исходного состояния. Это не проверка переноса связей через CSV.

## Наблюдаемые правила

«Каскадная сортировка» — однократное действие с подтверждением «Да / Отмена», без редактора ключей или направления.

На этом примере результат соответствует **стабильной сортировке по началу, затем завершению по возрастанию, отдельно среди детей каждого родителя**:

- Корни: A Early root → B Group → Z Late root.
- В B Group: N Nested → Z same short → A same equal → Y same long → Z late child.
- В N Nested: A nested early → Z nested late.
- Две короткие задачи с началом 03.11 оказались перед длинной с тем же началом.
- Z same short осталась перед A same equal при одинаковых датах: это не алфавитный порядок.
- Принадлежность всех десяти элементов родителям сохранилась; изменились порядок и WBS. Ветка N Nested осталась целой, хотя её поздний ребёнок идёт выше более ранних прямых детей B Group: это не глобальная плоская сортировка.

Сопоставлены видимые строки по DOM-идентификаторам задач, имена, WBS и обе отображаемые даты. Родители восстановлены из видимого WBS. Даты совпали для всех элементов. У стрелки сохранились DOM-идентификатор и доступное описание концов; она осталась нарисована между теми же задачами.

## Повторный опыт и сохранение

1. Перетаскиванием A same equal поставлена перед Z same short, а Z Late root — перед A Early root. Родители и даты не менялись.
2. «Отмена» в подтверждении сортировки оставила все строки без изменений.
3. «Да» снова восстановило хронологический порядок корней, но **сохранило новый порядок равной пары A → Z**. Вместе с первым опытом это подтверждает сохранение текущего относительного порядка при равных датах, а не сортировку по имени или исходному ID.
4. После полной перезагрузки страницы совпали все ID/тексты строк второго результата; стрелка также сохранилась. Это не только временное отображение.

## Undo: важное отличие

После первого запуска **Ctrl+Z не восстановил исходный порядок**. Вместо этого исчезла ранее созданная связь; сайт показал «Отменено — Зависимость удалена». Строки остались отсортированными.

Кнопка Redo восстановила связь. Повторная проверка кнопкой Undo на панели дала тот же результат: удаление связи без отмены сортировки. Затем связь снова восстановлена кнопкой Redo. Таким образом, в проверенной последовательности каскадная сортировка пропускается историей Undo.

Для будущей реализации Desktop требование из [плана](PARITY_PLAN.md) остаётся прежним: структурная сортировка должна быть одной отменяемой операцией. Это будет сознательным отличием от наблюдаемого поведения сайта, а не заявлением о совпадающем Undo.
