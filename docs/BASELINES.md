# Базовые планы — 0.13

Этап 5 из [плана](PARITY_PLAN.md): явно сохранённые снимки исходных дат, а не переименованный буфер Undo.

## Создать и выбрать

В заголовке проекта нажмите **Базовые планы** (▱ в узком окне).

- Введите уникальное имя и нажмите **Создать снимок** либо Enter в поле имени.
- Сохраняются **все элементы проекта**, независимо от поиска и свёрнутых групп: стабильный ID, имя, тип, начало и завершение. Для группы записываются её вычисленные границы на момент создания; вехи и пустые группы сохраняются тоже.
- Новый снимок выбирается для сравнения автоматически. Можно хранить несколько именованных снимков; одноимённые/пустые имена отклоняются без частичных изменений.
- Выделение строки списка только выбирает кандидата. **Использовать** (или двойной щелчок) включает его; **Не показывать** снимает выбранное сравнение.
- **Удалить…** требует подтверждения. Удаление активного снимка также снимает сравнение, но не меняет задачи.
- Закрытие окна отбрасывает лишь ещё не созданное имя; уже подтверждённые операции не отменяются скрыто.

Создание, выбор, снятие сравнения и удаление — обычные изменения проекта с dirty state и Undo/Redo. Сам снимок живёт в проекте: после сохранения и повторного открытия, когда Undo пуст, он по-прежнему существует. Выбор снимка **не восстанавливает** старое расписание.

## Что сохраняется неизменным

Снимок хранит даты/типы/имена по ID. Перенос, растяжение, смена календаря/иерархии, переименование и пересчёт зависимостей не переписывают его.

- Новый после снимка элемент не получает выдуманных нулевых дат или отклонений.
- Существующий переименованный элемент сопоставляется по ID, не по тексту имени.
- Запись удалённого элемента остаётся в снимке и JSON. Список сообщает число совпавших, новых и удалённых элементов; удалённые строки не добавляются призраками в текущую таблицу/экспорт.
- Для группы сравниваются текущие вычисленные границы с зафиксированными старыми, а не заново вычисленные старые даты по оставшимся детям.
- В этом варианте не сохраняются прежние стоимости, трудозатраты, назначения, связи, календарь или полная структура для восстановления проекта. Команд перезаписи снимка, восстановления задач и возврата расписания из него нет.

## Диаграмма и поля

Выбранный план показывается тонкими серыми полосами под текущими блоками; исходные группы имеют концевые отметки, вехи — маленькую отметку-точку. Полосы не принимают ввод и не мешают изменению задач. Масштаб/прокрутка общие с диаграммой. Критический путь продолжает анализировать **текущий** план; базовые полосы не становятся красными и не участвуют в его ограничениях.

**Поля → Стандартные** добавляет четыре изменяемых по ширине, но **read-only** столбца:

- Базовое начало.
- Базовое завершение.
- Δ начала, кал. ч.
- Δ завершения, кал. ч.

В свойствах доступны исходные дата/время и те же отклонения. Для отсутствующего в снимке элемента явно показывается отсутствие данных, а поля остаются пустыми.

**Δ = текущая дата/время − исходная дата/время в календарных часах**. Положительное — позже, отрицательное — раньше. Это не рабочая длительность и не резерв критического пути: пятница → понедельник может дать +72 календарных часа при гораздо меньшем числе рабочих часов.

Графика пока имеет существующую дневную точность; изменение времени внутри дня видно в полях/отклонении, но не выдаётся за полноценную почасовую шкалу. Даты выбранного снимка расширяют диапазон диаграммы для совпадающих элементов. Для объединённого диапазона свыше 100 лет расширение отключается с сообщением; исходные значения не удаляются и остаются доступны в полях. Удалённые элементы диапазон не расширяют.

## Файлы и экспорт

**Schema 7** хранит `baselines` и `active_baseline`. Каждый снимок имеет ID, имя, дату создания и собственные записи дат/типов/имён. Это не вложенный `Project` с рекурсивной историей. Списки/записи снимков не разделяют изменяемые контейнеры с историей или загруженным JSON.

Схемы 1–6 читаются без базовых планов, сохраняя прежние данные. Версии приложения до 0.13 новый файл не прочитают; оставьте отдельную старую копию перед новым сохранением.

- **PDF/PNG:** отдельная опция **Выбранный базовый план**. По умолчанию включена, если выбран снимок. Даты видимых экспортируемых элементов расширяют стандартный диапазон; свой диапазон явно обрезает и базовые полосы. Имя снимка печатается в заголовке при сравнении/выбранных базовых полях.
- **Табличные поля:** четыре значения доступны независимо от флажка графических полос. CSV хранит ISO дату/время и числовые отклонения; Excel — настоящую дату/время с долей суток и числовые часы. Даты до 1900 года сохраняются как ISO-текст, а особенность Excel 1900 года учтена.
- **XML:** только выбранный снимок для совпадающих текущих элементов записывается в стандартный Task `Baseline` с номером 0, `Start/Finish`; имя добавляется в Notes. Другие снимки и архивные удалённые записи остаются в JSON, а не притворяются полным переносом истории в MS Project. Импорт в настоящий MS Project по-прежнему не сертифицирован.
- Нет активного снимка — графический флажок отключён; программный запрос сравнения без снимка отклоняется. Весь экспорт использует замороженную копию проекта и не меняет выбранный план, задачи или историю.

## Проверка

66 новых проверок: 31 доменная/контроллерная, 22 UI и 13 экспортных. Охвачены неизменность дат, группы/вехи, несколько снимков, стабильные ID, новые/удалённые элементы, выбор/удаление/Undo, повторное открытие без истории, схемы 1–7, повреждённые снимки, пустой снимок, знак/единицы отклонений и защита от расширения диаграммы на столетия.

Реальный Qt-ввод проверяет заголовок в ширинах 1000/1366/1920 и обеих темах, Enter/Close/подтверждения, read-only поля и изменение их ширины, геометрию полос/масштаб, настоящее растяжение задачи после отрисовки кадра, инспектор, крупный шрифт и закрытие окон. Экспорт проверяет все пять форматов, замороженный снимок, серые полосы, XML Baseline 0 и Excel дату/время/эпоху.

Итог: **669 тестов прошли**, Ruff без замечаний; активная Python LSP-диагностика ошибок без находок. QML проверялся настоящим движком/вводом, а не отсутствующим QML LSP.

Wheel `gantt_desktop-0.13.0-py3-none-any.whl` временно установлен отдельно: 31 упакованный Python/QML-файл совпадает с исходником. Проверены нативное создание/выбор, настоящий перенос блока на 7 дней с сохранением старых дат, обе темы, сохранение/повторное открытие без Undo, пять форматов и отсутствие ошибок QML. Независимый openpyxl подтвердил тип `datetime`, время 09:00/18:00 и числовое отклонение +168 ч. Валидатор использовался только временно; runtime-зависимости, глобальная установка и реальные настройки не менялись.
